# BDL Pool — Next.js 16

The website uses Next.js 16 (App Router), React and TypeScript. It builds to
static HTML, CSS and JavaScript in `out/` for `bdl-pool.com` on GitHub Pages.
Bitcoin Core, CKPool, the API and monitoring run independently.

## Develop and verify

Use Node.js 20.9 or newer (CI uses Node.js 24):

```sh
npm ci
npm run dev
```

Production verification:

```sh
npm run build
npm run typecheck
npx playwright install chromium
npm run test:e2e
```

`npm run preview` serves the production export at `http://127.0.0.1:3000`.
There is no Node.js server to install on the mining machine. `next start` is
not used with the static export.

## Sources

- `app/(fr)/` and `app/(en)/en/`: the twelve French/English page components and
  language-specific document layouts. All existing URLs are preserved.
- `components/`: shared React navigation, theme control, page shell and icon sprite.
- `lib/pages.ts`: routes, page labels and SEO metadata.
- `assets/`: the existing styles, fonts, images, charts and live-data tools.
- `config.js`: public API, snapshot and Stratum configuration only.
- `app/sitemap.ts`, `app/robots.ts`: crawl files generated by Next.js.

`tools/prepare-public.mjs` stages web assets into the ignored `public/` directory
before development/build. It copies the OpenAPI contract, public status snapshot
and CNAME, but never the Python API server or monitoring source code. Edit the
original assets/configuration, not the staged files.

The data tools initialise after React hydration. They load configuration before
consumers and Chart.js before the chart adapter. Navigation uses ordinary
document links to give each page's existing timers/listeners a fresh lifecycle.
Unknown or unavailable readings remain unknown; the public API is unchanged.

## Publishing

`.github/workflows/web.yml` builds and browser-tests the export, then publishes
`out/` with the GitHub Pages actions on pushes to `main`. Pull requests and the
migration branch are built and tested without deploying.

For the first deployment, GitHub Pages must use **GitHub Actions** as its source
(repository Settings → Pages → Build and deployment). The workflow attempts to
enable this using `actions/configure-pages`; repository permissions may require
the owner to select the source once. Keep the custom domain `bdl-pool.com` and
HTTPS enabled. No DNS, API or Stratum change is needed.

The previous root HTML files remain as a temporary fallback for the existing
branch-based Pages publication until that first deployment succeeds. They are
not Next.js sources and must not be edited. The old Python page builder and its
templates are retired; edit the React pages instead.
